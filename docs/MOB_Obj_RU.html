📖 Руководство по Object Editor

Полное руководство по редактированию игровых объектов Evil Islands (файлы *.mob)

Автоприменение: При включении (Настройки → Автоприменение) изменения автоматически сохраняются при переключении на другой объект или поле. Не нужно нажимать Применить (F5) каждый раз.

Секция объектов (0x0000B000)

В Проклятых Землях есть 8 типов объектов, все они расположены в секции объектов.

1. Объекты (0x0000B001)

Статические объекты на карте: здания, камни, деревья, мебель и т.д.

Общие поля

ПолеСигнатураТипОписание
ID0x0000B002DWordУникальный числовой идентификатор. Должен быть уникальным для всех объектов на карте. Используется в скриптах через GetObject() как число и через GetObjectByID() как строка.
Type0x0000B003DWordКод типа объекта. Определяет, как движок обрабатывает этот объект.
ParentID0x0000B012DWordID родительского объекта. Используется для наследования объектов друг от друга.
Player0x0000B011ByteНомер дипломатической группы (0-31). Определяет принадлежность.
InScript0x0000B013ByteМногосложный параметр, влияет на динамичность объекта при работе с ним с помощью скриптовых процедур и в пограничных вариантах, отличных от базовых игровых ситуаций. Обязательно нужно выставлять равным 1 для корректной работы с объектами через скриптовые процедуры, для остальных может быть равным 0.
DropShadow0x0000B014Byte1 = отрисовывать тень под объектом. 0 = без тени.
Name0x0000B004StringВнутреннее имя на карте. Используется для читабельности. Регистр не учитывается движком.
Template0x0000B006StringИмя модели из 'Res/figures.res' (например, 'fence00', 'stwali1').
Parent0x0000B00EStringВнутреннее имя родительского объекта. Используется для читабельности. Регистр не учитывается движком.
Texture10x0000B007StringИмя первичной текстуры из 'Res/textures.res'.
Texture20x0000B008StringИмя вторичной текстуры из 'Res/textures.res'.
QuestInfo0x0000B016StringСтрока с информацией о квесте. Если указанное условие будет = 1, то юнит будет подсвечен квестовым маркером на карте. Может использоваться даже без наличия квестов в базе - для подсветки нужных внеквестовых юнитов.
Position0x0000B0093FloatsМировые координаты (X, Y, Z) в WCS. Формат: x, y, z
Rotation0x0000B00AQuaternionОриентация в виде кватерниона W,X,Y,Z. Используйте поля XYZ в градусах внизу справа для удобного редактирования поворота сущности.
Complection0x0000B00C3FloatsКоэффициенты масштаба (X, Y, Z). 1.0, 1.0, 1.0 = нормальный размер.
Comments0x0000B00FStringПроизвольный комментарий. Не используется движком, только для заметок в редакторе.
Parts0x0000B00DMultiStringСписок частей подобъекта. Одна часть на строку. Определены в заголовочном *.mod файле модели. Если пусто, то используются все части модели одновременно.
Совет: Вращение хранится как кватернион (W,X,Y,Z). Значение по умолчанию "без вращения" — 1.0, 0.0, 0.0, 0.0. Используйте поля Rotation XYZ (внизу справа) для установки вращения в градусах — кватернион обновится автоматически.

2. Юниты (0xBBBB0000)

Живые сущности: персонажи игроков, NPC, враги, существа. Юниты имеют все поля Объектов ПЛЮС дополнительные поля ниже.

Специфичные поля юнитов

ПолеСигнатураТипОписание
Import0xBBBB000AByte1 = юнит нуждается в использовании части параметров, описанных ниже (с "Armors" по "Stats"). 0 = все берется из 'Res/database.res/units.udb'.
Prototype0xBBBB0002StringИмя прототипа из 'Res/database.res/units.udb' (например, 'Human Hero', 'Rick', 'HareF0', 'PigF0').
Armors0xBBBB0009MultiStringЭкипированные предметы брони. Один предмет на строку. Формат: имя_предмета.материал[зачарование]
Weapons0xBBBB0008MultiStringЭкипированное оружие. Тот же формат, что и у Armors.
Spells0xBBBB0007MultiStringВзятые заклинания. Формат: прототип{руна;руна;...}
QuickItems0xBBBB0006MultiStringПредметы быстрого использования (жезлы, свитки). Тот же формат, что и у Armors.
QuestItems0xBBBB0005MultiStringКвестовые предметы в инвентаре. По одному на строку.
Stats0xBBBB0004StatsХарактеристики персонажа.

Слоты логики

Каждый юнит имеет 5 слотов логики (с Логики 1 по Логику 5). Используйте выпадающий список "Логика" для переключения между:
  • Свойства юнита — основные поля юнита (выше)
  • Логика 1-5 — конфигурации поведения ИИ

3. Рычаги (0xBBAC0000)

Интерактивные механизмы: двери, переключатели, ворота, активация ловушек. Имеют все поля Объектов ПЛЮС:

ПолеСигнатураТипОписание
Science0xBBAC0006DWord3Требования для открытия: ID квестового предмета, количество навыка, способность рук. Формат: flags, questitemid, skill
CurrState0xBBAC0002ByteТекущее состояние (0 = выключен, 1 = включен). Используйте GetLeverState() в скриптах.
TotalStates0xBBAC0003ByteОбщее количество состояний, которые может иметь рычаг.
Cycled0xBBAC0004Byte1 = рычаг можно переключать многократно. 0 = одноразовое использование.
Door0xBBAC0007Byte1 = этот рычаг управляет дверью. 0 = обычный рычаг. К дверям персонаж постарается подступать именно с передней или задней сторон, описанных математически в 'Res/database.res/levers.ldb'.
CalcGraph0xBBAC0008Byte1 = пересчитывать граф поиска пути ИИ при переключении.
Внимание: Для дверей и прочих объектов, влияющих на проходимость, необходимо устанавливать CalcGraph = 1.

4. Ловушки (0xBBAB0000)

Зоны нанесения урона или срабатывания эффектов. Имеют все поля Объектов ПЛЮС:

ПолеСигнатураТипОписание
TrDiplomacy0xBBAB0001DWordДипломатическая группа, которую атакует ловушка. -1 или 0xFFFFFFFF = атакует всех.
Spell0xBBAB0002StringЗаклинание или эффект, применяемый при срабатывании. Формат: прототип{руна;руна;...}
Reloading0xBBAB0005Byte1 = ловушка может срабатывать многократно. 0 = одноразовая.
CastOnce0xBBAC0005Byte1 = применять заклинание только один раз, 0 = наносить удары по всем целям сразу.
Areas0xBBAB00033FloatsArray2D зоны срабатывания. Каждая строка: x, y, area.
Targets0xBBAB00042FloatsArrayЦелевые точки, изначально заготовленные для разрядки в них магических ловушек. Каждая строка: x, y.
Активация ловушки: Используйте ActivateTrap(GetObjectByID("id"), 1) в скриптах для активации, или 0 для деактивации.

5. Факелы (0xBBBF0000)

Светоизлучающие объекты со звуком. Имеют все поля Объектов ПЛЮС:

ПолеСигнатураТипОписание
LightPoint0xBBBF00023FloatsСмещение точки излучения света от позиции объекта. Формат: x, y, z
Power0xBBBF0001FloatИнтенсивность света. Положительное = свет, отрицательное = тьма.
Sound0xBBBF0003StringПуть к звуковому файлу (например, nature\fire\small.wav). Пусто = без звука.

6. Освещение (0x0000AA01)

Чистые источники света (без физической модели). Проще, чем Факелы.

ПолеСигнатураТипОписание
ID0x0000AA05DWordУникальный идентификатор.
Shadow0x0000AA06Byte1 = отбрасывает тени. 0 = без теней.
Position0x0000AA043FloatsПозиция света (абсолютная). Формат: x, y, z
Color0x0000AA073FloatsЦвет RGB (каждый от 0.0 до 1.0). Формат: R, G, B
Radius0x0000AA02FloatРадиус света. Положительное = свет, отрицательное = тьма.
Name0x0000AA03StringВнутреннее имя.
Comments0x0000AA08StringЗаметки редактора.
Примеры цветов: Тёплый свет огня = 1.0, 0.6, 0.2. Холодный лунный свет = 0.5, 0.6, 1.0. Зелёный яд = 0.2, 1.0, 0.2.

ПолеСигнатураТипОписание

9. Логики юнитов (0xBBBC0000)

Каждый юнит имеет до 5 слотов логики. Логики определяют поведение ИИ: маршруты патрулирования, точки охраны, агрессию и многое другое.

Поля логики

ПолеСигнатураТипОписание
AlarmCond0xBBBC000BByteКод условия тревоги. 0 = если видит врага, 1 = если атакован, 2 = если было вызвано подозрение.
CallForHelp0xBBBC000CFloatРадиус призыва союзных юнитов на помощь.
Cyclic0xBBBC0002Byte1 = последняя точка патруля является переходной к первой, 0 = с последней точки патруля переход идёт в обратную сторону.
AggrMode0xBBBC000EByteРежим агрессии (0 - абсолютная агрессия, 1 - агрессия только как месть, 2 - абсолютная боязнь врагов, 3 - абсолютная боязнь врагов и игрока).
Active0xBBBC000DByte1 = юнит активен всегда, 0 = юнит активен только в близи около 50 метров от текущей партии игрока.
Model0xBBBC0003DWordКод модели поведения ИИ. 0 = точка, 1 = охранник, 2 = патруль, 3 = часовой, 4 = игрок, 5 = тревожный охранник. Точка: стоит на месте и смотрит в одну сторону. Охранник: охраняет указанный круг, вставая поворачивается к случайной точке. Патруль: патрулирует строго по заданным точкам, если точки не содержат действия - то поворачивается на них случайно. Часовой: стоит на месте и поворачивается в случайные точки. Игрок: управление передано девайсам игрока или скриптмодулю карты. Тревожный охранник: делает то же, что и охранник, но в местах вызванной тревоги.
Radius0xBBBC0004FloatРадиус охраны.
Wait0xBBBC000AFloatВремя ожидания на каждой точке охраны (в игровых тиках).
Point0xBBBC00053FloatsЦентральная точка для проведения охраны или часовничества. Формат: x, y, z
Used0xBBBC0007Byte1 = этот слот логики используется.
AlarmNumb0xBBBC0006ByteНомер переменной тревоги, на которую реагирует эта логика.

Точки охраны (0xBBBD0000)

Точки охраны определяют путевые точки для поведения патрулирования и охраны. Каждая точка имеет:
  • Координаты — позиция путевой точки (X, Y, Z)
  • Действия — что делает юнит в этой точке
ПараметрСигнатураОписание
x, y, z0xBBBD0001Координаты точки, на которую встанет юнит

Действия точек охраны (0xBBBE0000)

Каждая точка охраны может иметь несколько действий. Формат в редакторе действий:

x, y, z; времяОжидания; скорость; флаги
x, y, z; времяОжидания; скорость; флаги
ПараметрСигнатураОписание
x, y, z0xBBBE0001Координаты точки взгляда (куда смотрит юнит)
времяОжидания0xBBBE0002Как долго оставаться в этом действии (игровые тики, 15 = 1 секунда)
скорость0xBBBE0003Скорость поворота перемещения к этой точке
флаги0xBBBE0004Флаги поведения (битовая маска): слабо реализовано в игре, 0 - обычное поведение, 1 - будет отдыхать на точке.
Важно: При редактировании точек охраны вы должны сначала выбрать конкретный слот логики (Логика 1-5) из выпадающего списка. Точки охраны принадлежат отдельным слотам логики, а не юниту в целом.
Рабочий процесс:
1. Выберите юнит в списке
2. Выберите слот логики из выпадающего списка (например, "Логика 1")
3. Отредактируйте поля логики (Active, Radius, Wait и т.д.)
4. Нажмите "Добавить точку" для создания точек охраны
5. Выберите точку для редактирования её координат и действий
6. Нажмите Сохранить (F5) или полагайтесь на Автоприменение

10. Общие советы

Автоприменение

При включении (Настройки → Автоприменение) любые изменения автоматически сохраняются, когда вы:

  • Кликаете на другой объект в списке
  • Переключаетесь на другое поле
  • Переключаете вкладки или слоты логики

Добавление объектов

Нажмите "Добавить" для создания нового объекта из шаблона по умолчанию. Новый объект является копией встроенного шаблона для этого типа.
